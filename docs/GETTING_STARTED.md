# Getting started

This is an independent public-source distribution of Madar Al Bayan. Its setup and data packaging are adapted from the deployed application. It does not contain production credentials, visitor records or the publisher corpus behind the hosted demonstration.

For a zero-install product review, use the [live platform](https://madar-al-bayan.asash263164.chatgpt.site). For engineering review, follow the steps below.

## Requirements

- Node.js **22.13 or newer** and the **pnpm version pinned in `package.json`**.
- Internet access for dependency installation, optional publisher downloads and configured services.
- An interactive terminal for generating an administrator password hash.
- `curl` if your network sets an `HTTPS_PROXY`; the starter importer uses it to honor that configured proxy.

The stack uses Vinext with Next-style routes and a local Cloudflare Worker/D1 environment. It is not a static site. A generic static-file host cannot run its search, review database or mail routes.

## 1. Install and start with an empty local collection

From the repository directory:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm setup
pnpm db:migrate:local
pnpm dev
```

Open **http://localhost:5173**. If the runtime reports another port, use that reported address. `pnpm setup` creates minimal empty data schemas without downloading publisher text. The local collection starts at zero; deployment-wide catalog metadata in the References page is documented inventory, not the quantity installed on your machine.

Local D1 state is stored under `.wrangler/state`. The committed migration files create the schema; no production database is imported. Re-run `pnpm db:migrate:local` after a schema update. Do not delete local state unless you intend to discard your local messages and sessions.

## 2. Import a deliberately small official starter collection

```bash
pnpm sources:starter
pnpm smoke:starter
```

The importer requests five selected HadeethEnc records and Quran verse `1:1` in the nine supported languages. When every selected item is available, that is **45 hadith text records and 9 verse text records**. It retains publisher fields, records request URLs and response hashes, and creates compatible full-text indexes. The imported JSON and indexes are ignored by Git.

The starter is not the full hosted collection. Its manifests record what was actually downloaded; missing translations or failed requests are reported rather than filled with generated text. To retry or refresh:

```bash
pnpm sources:starter -- --refresh
```

Inspect `public/sources/starter-manifest.json` locally. Preserve publisher attribution and review [Sources](SOURCES.md) and [third-party notices](../THIRD_PARTY_NOTICES.md) before importing or redistributing additional material. Importing sample content does not grant a license to republish an entire database.

## 3. Configure optional server-side services

Copy `.env.example` to **`.dev.vars`** and fill only the features you intend to test. Restart the development server after changing Worker variables. `.dev.vars` is ignored and must never be committed.

| Variable | Purpose |
|:---|:---|
| `OPENAI_API_KEY` | Server-side model access for free-question understanding and semantic evidence selection |
| `OPENAI_MODEL` | A model ID actually available to your account with Responses API and structured-output support |
| `ADMIN_USERNAME` | Your own administrator login name |
| `ADMIN_DISPLAY_NAME` | Display name for your local administrator |
| `ADMIN_PASSWORD_HASH` | Hash generated by the interactive command below |
| `RESEND_API_KEY` | Transactional mail provider credential |
| `MAIL_FROM` | A sender address/domain verified for your mail account |
| `COMMITTEE_REVIEWER_IDS` | Optional trusted hosting-identity reviewer IDs for legacy case routes; not required for the main standalone administrator inbox |

The reference deployment used `gpt-6-astra`. That name records its configuration; **this repository does not supply model entitlement**. Choose an available compatible model and validate it in your deployment. If model credentials are missing or a model request fails, unrestricted semantic search does not become a local language model. Exact-topic or direct-reference paths may still operate independently.

Do not place secrets in browser variables, URLs, issue reports, screenshots or README examples. No production key or administrator account is included in this release.

## 4. Configure and test the administrator inbox

```bash
pnpm admin:hash
```

Enter a new password when prompted; input is hidden. The script requires at least twelve characters and prints a salted PBKDF2 hash. Store the resulting value in `.dev.vars` as `ADMIN_PASSWORD_HASH`, together with your own `ADMIN_USERNAME`. Do not reuse any earlier demonstration password.

After applying migrations and restarting the server, open `/admin`. The primary inbox uses its own administrator session. Local hosting identity is mocked for development and must not be mistaken for production authorization of the legacy committee/case routes.

Use a synthetic question and an address you control to test submission and reply. Without working mail credentials and a verified sender, email cannot be delivered. A stored question and a delivered reply are separate events. Before exposing an independent deployment, test administrator access, cross-origin protections and the complete delivery path.

## 5. Verify and build

```bash
pnpm typecheck
pnpm test:contracts
pnpm build
```

The contract suite uses controlled responses; it does not call a paid model or claim live publisher availability. The repository's quality workflow performs these checks without downloading the hosted corpus or using production secrets.

For the built Worker locally:

```bash
pnpm start
```

Use the URL printed by Wrangler. The built Worker and development server use the project-local D1 state. A static `index.html` preview is insufficient.

## Extending the corpus

The public package retains source adapters and import utilities for review. Some historical import scripts require additional Python packages and work-specific publisher files; they are not the first-run setup. Review their inputs, notices and current official APIs before running them. Rebuild indexes after any authorized corpus change.

Treat [recorded deployment counts](evidence/source-inventory.json) as a dated inventory, not expected assertions for your starter data. Corpus-backed tests are identified separately in [Evaluation](EVALUATION.md).

## Troubleshooting

| Symptom | Check |
|:---|:---|
| Missing generated JSON on a fresh checkout | Run `pnpm setup`; build/typecheck/dev scripts also prepare empty schemas |
| `no such table` on message routes | Apply `pnpm db:migrate:local` to the same working directory and local state path |
| Free questions cannot return semantic results | Check server-side model configuration, account access and provider response; never replace missing evidence with generated answers |
| Publisher import exits with failures | Read the local starter manifest; verify the publisher request and retry with `--refresh` |
| Administrator setup incomplete | Configure your username and generated hash, then restart the Worker |
| Reply is stored but mail fails | Check sender verification and transactional mail credentials separately |
| A source link opens data rather than an article | Some publishers provide record data without a dedicated reading-page URL; see the API/source documentation |

For deployment beyond local evaluation, configure your own Worker, database, secrets, mail sender and access controls. The sanitized hosting manifest deliberately contains no production project ID or account binding.

For independent hosting and runtime-port requirements, see [Deployment](DEPLOYMENT.md). The public Worker strips untrusted hosting-identity headers in production; legacy hosting-only routes require a verified identity adapter.
