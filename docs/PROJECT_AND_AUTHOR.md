## Why Madar Al Bayan exists

A person exploring Islam may not speak Arabic, know which reference to consult, or know the terminology used in a publisher's index. A natural question can also contain several requests or an important condition that a single matching keyword does not capture.

Madar Al Bayan addresses this discovery problem through a browser-based platform. Visitors write in a supported language, inspect relevant published passages and follow the source. People learning about Islam for the first time and those seeking a specific reference can use the same direct interface.

The project was developed for an Islamic AI challenge focused on cross-cultural communication and introducing Islam. Its contribution combines multilingual access, context-aware retrieval, traceable evidence and organized human correspondence in one experience.

## The decisions that define the product

| Product decision | Purpose |
| :--- | :--- |
| A focused question-first interface | Make the first interaction understandable without a technical explanation |
| An explicit reference allowlist | Keep the knowledge scope under project control |
| Published text and existing publisher translations | Preserve the source's wording and attribution |
| Context assessment before displaying evidence | Consider the actual request, conditions and relevant parts of a compound question |
| Ranked passages with inspectable references | Help the reader compare evidence and examine where it came from |
| Voluntary human review when evidence is unavailable | Give the questioner a follow-up route without inventing an answer |
| Numbered correspondence with language and recipient retained | Let the administrator concentrate on reviewing and answering the enquiry |
| Separate current coverage and future expansion | Make the product's scale and remaining work understandable |

## Present scope and intended progress

The documented reference deployment supports nine languages and nine current references with different capabilities. The [source directory](SOURCES.md) and [language tables](LANGUAGES.md) explain the collection's verified counts, publisher coverage and planned additions. The [feature inventory](FEATURES.md) links implemented behavior to its code, while [Evaluation](EVALUATION.md) records the tests and their limits.

The next stage is to improve measured retrieval quality, close demonstrated content gaps, expand verified reference coverage and strengthen follow-up operations. The aim is a useful, understandable service whose answers remain connected to their evidence and whose human-review responsibilities remain clear.
